# 海豹关卡谱面说明

本谱面完成当前项目的三键海豹关卡，使用现有音乐与动画，保留已手工标记的开头动作。它是本项目改编谱，并非逐帧复刻 Wii 原作的动作分配。

- 音乐：`Assets/Resources/Art/Level_cellanim/Music/haibao.mp3`。
- 网格：133 BPM，44,100 Hz，零起始偏移，每拍约 0.451128 秒。
- Unity 实际导入长度：4,687,488 样本，106.292245 秒。MP3 容器报告 106.204100 秒；游戏应使用 `AudioClip.samples` 判断结束。
- 玩家/同伴轨：`haibaoEventID`，235 个输入，包括开头 5 个点头及主段 230 个输入。
- 队长轨：`PeopleEventID`，起步、全程同拍点头、口令说话；与玩家/同伴轨使用相同的整数样本换算。
- 最后一击：第 226 拍，4,496,211 样本，101.954898 秒；其后留约 4.337 秒音乐收尾。

## 拍位依据

开头保留原 22 个动作：第 7、9、11、12、13 拍点头；15 拍起左右交替；25.5 拍加一次翻转。原 506,629 样本的加拍点修正为 507,316 样本，所有点按相同公式四舍五入到整数样本，消除原两条轨之间的 1 样本差异。

主段在 15 至 226 拍维持行进。通过对现有音乐的重复口令片段作带通/高通波形互相关，发现 18 组三连口令。第一组三个音节约在 22.5、23、23.5 拍，回应节奏在 25、25.5、26 拍，与现有手工 25.5 拍标记一致。其余口令使用相同的两拍延迟，得到以下额外半拍：

```text
25.5, 41.5, 57.5, 73.5, 85.5, 97.5,
117.5, 133.5, 145.5, 151.5, 159.5, 167.5,
183.5, 191.5, 199.5, 213.5, 217.5, 221.5
```

共 212 个主段整拍与 18 个半拍，共 230 输入。未往四分之一拍网格添加装饰音符。

## 动作改编

普通行进交替使用 `left` 和 `right`，每次翻转包括额外半拍都会切换方向。以下短乐句改为 `diantou`，给现有 S 键与点头动画完整的游戏用途。六段动作属于项目编排，拍位保持在音乐网格上；不声称对应原版的每一次翻滚。

| 队长提示拍 | 点头起始拍 | 次数 |
| --- | --- | --- |
| 58 | 61 | 4 |
| 102 | 105 | 4 |
| 134 | 137 | 4 |
| 168 | 171 | 4 |
| 200 | 203 | 4 |
| 222 | 225 | 2 |

动作总计为 27 次点头、104 次左翻、104 次右翻。NPC 海豹与玩家目标共用 `haibaoEventID`，避免两套动作数据漂移。队长在三连口令第一音节、点头段提示时播放 `characterSpeak01`；其他动作拍播放 `characterDiantou`。同拍不同动画层的事件是有意保留的，不是重复输入。

## 修改与校验

谱面可编辑源为 `Tools/SealChart.json`，生成器只依赖 Python 标准库；修改后执行：

```powershell
python Tools/generate_seal_chart.py
python Tools/generate_seal_chart.py --check
```

生成器保留两个既有 Unity 资产的 GUID、脚本引用和事件 ID。校验覆盖：原开头动作不变、样本严格递增、235 输入、18 半拍、最短 0.5 拍间隔、全部输入位于音频范围内、足够收尾、队长拍位与输入一致、Koreographer 文本 payload 与小端整数索引一一对应。`--check` 不写入文件，也可用于后续回归检查。

音频口令识别也可复现（另需 PATH 中有 FFmpeg，Python 有 NumPy 与 SciPy）：

```powershell
python Tools/analyze_seal_audio.py
```

脚本取现有手工加拍前的第 23 拍口令为模板，300–2500 Hz 带通滤波后，对每个整拍作允许 ±20 ms 对齐的归一化互相关；0.65 阈值恰好找到上述 18 组，实际最弱匹配仍有 0.747。它只读音频和 JSON，不修改谱面，也不依赖在线服务。
